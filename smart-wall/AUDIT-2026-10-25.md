# Palettè internship audit — 25 October 2026

## Verdict

The project has substantial working functionality, but is not ready to describe as a completed deployed system. Stop adding decorative features. Fix image validation and navigation reliability, prepare proxy-safe deployment settings, and complete the public deployment requirement.

This is a local engineering audit, not a claim that every possible input, browser, security exploit or infrastructure failure has been tested. The compiled app was exercised in an isolated MongoDB database at localhost:4300. The owner's accounts, photos, administrator access and production data were not used or changed. Application source was not modified during this audit.

## Findings in priority order

### A1 — High: public deployment deliverable is missing

The supplied internship brief explicitly asks for a deployed cloud demonstration with a domain. The project remains local. Local production-mode tests are useful but do not fulfil that deliverable or prove availability.

Finish: deploy Angular/Express with managed MongoDB, HTTPS, stable JWT configuration and backups. Record the public URL; check registration, login, upload, editing, save/reopen, download and admin permissions after an actual redeploy. A paid custom domain is not expressly prescribed by the screenshots; use a suitable provider domain unless the mentor requires a custom one. Gmail remains optional.

### A2 — High: saved image validation accepts corrupt content

Source: server/designs.mjs:17–20. The original is recognised by a few signature bytes; preview validation reads PNG signature/IHDR dimensions without decoding the image. A file does not have to be a complete renderable photo to pass.

Reproduced against the isolated API:

- POST /api/designs with an 8-byte PNG signature as photo returned 201.
- A 24-byte PNG signature/IHDR stub as preview also returned 201.
- The gallery displayed a broken image for the accepted stub preview.

Impact: the server reports a successful save for unusable data. Header/dimension checks alone do not establish image integrity or bound original decoded pixel dimensions. This is a validation/data-integrity issue, not evidence of executable image code or a confirmed account compromise.

Fix: validate/decode complete images server-side using a maintained decoder with byte/pixel/resource limits; reject corrupt originals/previews and mismatched aspect/dimension metadata before GridFS writes. Preserve original photo fidelity when required. Add negative tests for truncated PNG/JPEG/WebP, forged header dimensions, extreme decoded sizes and original/preview mismatch. Browser-side file type validation is not sufficient for API clients.

Evidence: review/audit-probes.mjs and review/audit-probes.json.

### A3 — High for cloud deployment: proxy clients share login rate limits

Source: server/mean-api.mjs:77 and other limit keys use req.socket.remoteAddress. An incoming reverse proxy's TCP address is consequently used rather than a verified original client identity.

Reproduction: requests bearing 31 different synthetic X-Forwarded-For addresses exhausted the same login bucket; a subsequent valid login bearing another address returned 429. The run produced 26 validation responses and 5 rate-limited responses because earlier audit logins had already used that bucket.

Inference for deployment: a typical load balancer can make unrelated users share this bucket, causing false lockouts. This was not tested through an actual AWS load balancer.

Fix: configure Express trust proxy for the actual trusted proxy topology and use the resulting client IP plus account-based limits. Do not blindly trust arbitrary X-Forwarded-For headers. Test separate clients behind the chosen proxy and spoofed forwarded headers. For multiple instances, use shared limiter state rather than process-local maps.

Evidence: review/audit-rate.mjs and review/audit-rate.json.

### A4 — Medium: page navigation does not survive refresh or provide normal browser history

Source: src/app/app.ts:25 and navigate() at line 104. The page is an in-memory field; navigation does not create stable page URLs/history entries.

Reproduced: navigated to Shades, refreshed, and landed on Home at the unchanged root URL. This also limits direct links to Dashboard, Patterns and Admin. Saved account designs survived; this finding is about page/navigation state.

Fix: use Angular routes for the required functional screens, preserve intended destinations after login, and verify refresh, copied URLs, Back/Forward and unauthorized admin navigation.

### A5 — Medium: unsaved work is easy to lose without a warning

Code inspection: the editor states that unsaved edits reset on refresh, but no dirty-state navigation/replacement/unload guard exists in the application. loadPhoto() replaces the current photo and selections after decoding; clear/reset actions also have no dirty-state protection. Internal header navigation preserves the mounted editor, which is useful, but a full refresh still destroys unsaved state.

Fix: track unsaved changes; warn before replacing the room, closing/reloading, or losing the editor. A temporary local draft is an optional improvement. Test that confirmation cancellation preserves the current room and that completed saves clear the warning.

### A6 — Medium: the upload KPI counts sample loads and reopened saves

Source: src/app/visualizer.ts:243 records upload inside loadPhoto(); both sample() and openSavedDesign() call it. Admin discloses this limitation, but the KPI label remains Room uploads, while the brief asks for the number of room images uploaded.

Observed: loading the sample and reopening a saved photo raised the upload count to 2 without two new user photo uploads.

Fix: distinguish new user uploads, sample loads and saved-design opens. Show actual upload events as the required KPI and keep the other events as optional usage details. Avoid describing current active-visit estimates as exact user session durations.

### A7 — Medium polish: broken characters in validation messages

Source: server/mean-api.mjs:79 and 82. Invalid-login input returns a corrupted dash sequence in the 8-to-128-character password instruction; the name-length instruction has the same issue.

Fix: replace the text with clean UTF-8 or plain ASCII such as "8-128 characters" and check all displayed errors. Add a small assertion for the actual validation message. This is visible evaluator-facing polish, not a cosmetic concern hidden in code.

### A8 — Medium assurance gap: existing tests miss realistic image and browser failures

The existing 81 tests pass even though A2 is reproducible. Backend image fixtures often use tiny images/header checks, and frontend tests run in jsdom. Passing the suite therefore does not establish realistic wall selection quality or actual browser end-to-end reliability.

Fix: keep the current tests, and add a small real-browser regression flow: register/login, upload real photo, outline wall, apply two colours and a pattern, save, reload, reopen, download and safely delete only disposable test designs. Add 5–10 varied room photos with bright/dark walls, shadows, similar-coloured furniture, frames, windows and multiple walls. Record where manual refinement is needed. This is a recommended test set, not a participant-count requirement from the brief.

## Quality improvements after the fixes

1. Preview realism: current motifs repeat in image coordinates, so they look flat on walls photographed at an angle. Perspective-aware placement would improve realism, but it is an enhancement; do not add AI, 3D or AR as a supposed Phase 1 requirement.
2. Small-screen editing: inspected controls fit, but the canvas sits far above the controls after scrolling. A compact preview/jump-back action would make fine adjustments easier while preserving the requested original preview layout. Tablet is required; phone polish is optional.
3. Accessibility: retain focus outlines and labels; add predictable focus on screen changes and accessible selected-state announcements. Check contrast, zoom/reflow and a full keyboard/screen-reader path before claiming accessibility compliance. Current audit does not establish WCAG conformance.
4. Performance: avoid unnecessary full-image repainting; consider requestAnimationFrame coalescing or a worker only if actual low-power tablet measurements show jank. Synthetic Node CPU medians at 1600×1067 were 28.51 ms solid, 28.44 ms dual and 49.01 ms Crosshatch; maxima across seven runs were 29.13, 33.63 and 53.54 ms. These exclude image decoding, wall selection, canvas drawing and network and are not browser frame timings.
5. Operational readiness: local backups pass integrity/restore tests, but production off-host backups, actual restore procedure, availability monitoring and retention responsibility still need deployment evidence. The custom backup implementation reads whole collections into memory; review its capacity before using it with a large user/media dataset.
6. Submission clarity: explain manual polygon/edge-based selection, actual MongoDB/GridFS storage, user/admin boundaries, measured limitations and the exact deployed URL. Do not claim AI detection, manufacturer-certified colour matching or measured reductions in repaint costs.

## What does not need to be added for the internship

Real Gmail delivery, email verification, password-reset emails, AI segmentation, native mobile apps, AR/VR, purchasing/payments and advanced 3D are not explicit Phase 1 requirements in the supplied brief. The email extras are intentionally disabled. A paid domain, a fixed participant count or a separate video/report are not expressly mandated by the supplied screenshots; check portal-specific instructions before treating them as compulsory.

1. Repair server image validation and add the failing negative cases.

4. Configure proxy-safe production rate limits and deploy with persistent MongoDB/HTTPS/backups.
5. Run the full evaluator journey against the public URL, including save/reopen after redeploy, admin updates, privacy checks and a tablet.
